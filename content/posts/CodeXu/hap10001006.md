二、逐版本更新要点
10.0.0  主页二级菜单（文件夹）
主页新增文件夹：设置 → 条目管理里可新建、改名、删除文件夹；删除文件夹只把其中条目移回主页，不删除条目。
条目可自由选择归属：新增/编辑条目时有「所在文件夹」选择器（不放入文件夹 / 各文件夹）。
文件夹为二级菜单：主页显示文件夹卡片（图标 + 名称 + 条数），点进去是与首页完全一致的条目布局，返回键或左上角‹可回主页。
设置页底部新增作者与联系方式：作者 Tszheoi Law、联系方式 pelakai@mail.tszheoi-law.top，仅设置页显示。
备份分区同步扩展：主页条目分区包含 folders，保证文件夹设置随备份迁移。

10.1.0  通知提醒与重复规则增强
账户管理每条记录新增提醒入口：可为订阅、银行卡、电话卡等设置一次性通知，提醒时间手动选择（日期 + 时间）。
待办新增提醒行：与截止日独立，可单独设置提醒时间；保存待办时写入，删除待办时自动清理。
首次设置提醒会申请通知权限（notificationManager.requestEnableNotification），未授权时给出明确提示。
提醒通过系统代理提醒（reminderAgentManager）排程：到点弹一条通知，不常驻通知栏、不需要后台进程；启动时自动重排未来提醒。
待办重复新增「周内选天」：可点选周一至周日任意组合（如周一三五），与快捷项互斥。
待办重复新增「自定义区间」：只选开始与结束日期，中间自动包含；周内选天与区间可组合（区间内每周指定星期几重复）。
重复规则实时摘要：如「每周 一、三、五 · 2026-10-01 ～ 2026-12-31」。
设置页新增「通知与提醒」：显示通知授权状态、列出全部提醒并可删除。

10.1.1  排序逻辑重做
文件夹与条目共用一套排序序号：主页上可交叉上下移动，不再「文件夹全在前、条目全在后」。
条目管理改为两段式：默认显示「主页排序」（文件夹与未分组条目混排），文件夹行提供「进入」。
进入文件夹后切换为「文件夹内排序」：只对该文件夹内的条目单独上下移动、编辑、删除。
条目在文件夹之间的移动通过编辑里的「所在文件夹」完成，移动后保留其排序值。
删除、修改后自动归一化排序，不产生序号空洞。


10.1.2  文件夹图标统一
文件夹图标由彩色 emoji 改为自绘 SVG 线性图标（ic_folder.svg，24×24、1.7px 描边、无填充）。
颜色跟随主题：深色模式浅灰、浅色模式中灰，与应用整体的黑白灰体系一致。
替换范围：主页文件夹卡片（19×19）与条目管理排序列表（16×16）。
10.1.3  一次备份覆盖全部
补齐遗漏的备份键：外屏背景图（img_bg_o_light / img_bg_o_dark）、记账账户迁移标记（ledger_acc_migrated）。
备份分区共 6 段、37 个键：主页条目与文件夹、记账、账户管理、验证器、待办与专注、设置项。
新增「全选 / 全不选」按钮，默认全部选中所选即完整备份。
备份页新增两段说明：一次备份包含哪些内容；以及从 TszTool 迁移到 Tsz+ 的操作方式。
备份文件格式升级为 version 2，新增 source 与 sections 字段；恢复仍按分区合并，不删除本地已有数据，旧的 version 1 备份仍可导入。

10.1.4  排序即时刷新
修复：主页排序点了上移/下移没有反应，需要退出重进才显示。
根因：排序列表数据源写成函数调用（Store.homeEntries()），未依赖任何组件状态，框架不会标记重绘。
改法：新增 @State homeList / folderList 作为数据源，并提供统一刷新入口 reloadHome()，挂在排序、增删改、改名、进入/返回等 8 处变更点。
主页网格同样改用 homeList，排序结果在主页立即可见。
10.1.5  提醒入口改文字
账户管理的提醒入口由时钟图标改为文字按钮：中文「提醒」、英文「Remind」。
样式与右侧「编辑」「删除」完全一致（字号 12、正文色、内边距 10/10/5/5），不再出现彩色 emoji。
10.1.6  文件夹内排序空白修复
修复：进入文件夹内排序后整页空白，看不到任何条目。
根因：「进入」按钮只切换了 editFolder 状态，未重算 folderList，渲染分支拿到空数组。
改法：进入时调用 reloadHome() 重算列表；同时为确实为空的文件夹补上占位提示，不再出现白屏。
三、本阶段重点说明
1. 主页二级菜单的数据结构
条目（items）新增 folder 字段，空串表示直接显示在主页；此外新增 folders 键保存文件夹列表。文件夹与条目各自带 order 字段，共用同一套序号，因此主页上可以混排。排序变更后会自动归一化为 0..n-1，避免序号空洞。
2. 提醒的实现方式
使用系统代理提醒（reminderAgentManager.publishReminder），应用无需常驻后台。
通知为一次性：到达设定时间弹出一条，不会长期挂在通知栏。
所需权限：ohos.permission.PUBLISH_AGENT_REMINDER（已在 module.json5 声明），另需用户允许通知。
提醒数据存入 reminders 键，随「待办与专注」分区一起备份；应用启动时重新排程未来提醒。
3. 重复规则的计算
勾选完成时按规则生成下一份：若设置了周内选天，则从当前日期逐日向后寻找第一个命中的星期，且不超出区间结束日；超出区间或找不到命中日时不再生成。快捷项（每天/每周/每月）在未选周内日期时生效，二者互斥但都可与区间组合。
4. 备份与迁移
备份格式为 {app, version:2, source, at, sections, data}，data 里每个键保存原始 JSON 字符串。恢复时按分区合并：数组按 id/name 去重追加，设置类本地优先，绝不删除本地已有数据，因此可以在 TszTool 与 Tsz+ 之间互导。注意验证器密钥使用 HUKS 加密，密钥属于各自应用沙箱，跨应用无法解开，迁移验证器需使用「导出 otpauth 链接清单」再重新导入。

四、已知限制
提醒的实际弹出依赖系统通知开关；若用户在系统设置中关闭本应用通知，提醒不会显示。
代理提醒的时间精度由系统调度决定，可能存在数分钟内的偏差。
验证器密钥不能跨应用迁移，需通过 otpauth 导出/导入。
文件夹层级只有一层（不支持文件夹嵌套文件夹）。
